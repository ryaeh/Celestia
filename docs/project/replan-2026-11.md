## 1. What changed in the world

| Finding | Source quality | What it means for Celestia |
|---|---|---|
| **OpenClaw** (local daemon, chat-app front ends, persistent memory, community skills registry) went viral in early 2026, then had the year's first big agent-security crisis: an RCE CVE, ~135k internet-exposed instances, malicious registry skills that also wrote into memory files. It runs **without mandatory approval**. | Security vendors (Trend, Palo Alto); counts are secondary **[VERIFY]** | The demand is real and the attack surface is exactly ours. Approval-first is now the product's strongest differentiator, not a security chore. Inbound chat-app bridges are the dangerous part. |
| Safer alternatives are shipping **approval flows** (Sai, Hermes Agent v0.8). | Secondary **[VERIFY]** | The approval card in the Console design is table stakes within months. |
| **Meta's Agents Rule of Two** (Oct 2025): in one session an agent may combine at most two of {untrusted input, sensitive data/systems, state change or external comms}; all three needs a human. **OWASP Top 10 for Agentic Applications** (Dec 2025). | Primary (Meta) | Celestia combines all three in many turns. Turn this into an enforced rule (see T08). |
| **Cloud assistants went standing/proactive:** Gemini "Spark" (24/7 background agent) and "Daily Brief" (inbox, calendar, tasks) announced at I/O, May 2026. | TechCrunch; safety details not given | A morning brief is expected. A **local** one (your to-dos, memory, last session, no cloud mailbox) is a real differentiator and needs no screen watcher. |
| **MCP spec 2026-07-28:** stateless core, `server/discover`, tasks as an extension, server-initiated requests replaced by **multi round-trip `input_required`** results, Roots/Sampling/Logging deprecated, DCR deprecated, `tools/list` should be deterministic and carries `ttlMs`/`cacheScope`, 12-month deprecation policy. | Primary (spec changelog) | Our `skills/mcp/` client needs a compatibility pass. `input_required` should route into the same approval UI. Deterministic tool lists make manifest hash pinning (T11) easier. |
| **Agent Skills / `SKILL.md`** is now a cross-vendor folder format (reported 40+ tools). | Secondary **[VERIFY]** | Our "Skill SDK" idea should adopt it, local-only and hash-pinned (OpenClaw's registry is the cautionary tale). Low priority. |
| **Local models:** Ollama library now has `gemma4` (e2b/e4b with audio+vision+tools; **12b** 7.7–8 GB), `qwen3.5` up to 9b (6.6 GB), `nemotron-3.5-bolt` (~8B, vision+tools+audio), `lfm3` (1.7–2B, now on Windows). Qwen3.6/3.8 are 27B+ and too big for 12 GB. | Primary (Ollama pages) | T02's open question ("8–9B needs a GPU run") has a wider candidate set. One multimodal model for chat + vision could remove the chat↔VL swap. Ollama's `/v1/audio/speech` exists but is macOS-only so far. |
| **Voice:** open full-duplex models exist (PersonaPlex-7B ~16.7 GB; MiniCPM-o 4.5 needs 12 GB+; NemotronLabs VoiceChat 11B is server-class and calls tools). Good small STT/TTS: Qwen3-ASR 1.7B, Granite Speech 2B, Moonshine v2 (CPU), **Kokoro 82M (CPU-capable)**, Qwen3-TTS 0.6B. | Mixed **[VERIFY]**; VoiceChat paper is primary | Full-duplex does not fit beside an LLM on 8–12 GB. Keep the cascade. **Kokoro on CPU is a better local fallback than text-only** when Orpheus fails. |
| **Memory benchmarks are vendor-run and contradictory.** Graph systems beat plain vector on LongMemEval in some reports; a 2026 paper claims ~90% with a single vector query and no graph. | Vendor / papers **[VERIFY]** | D4 ("mem0 + SQLite graph") is unmeasured on *our* data. Gate A tests extraction, not end-to-end recall. Add that eval before more memory work. |
| **Companion regulation:** California SB 243 in force since 1 Jan 2026 (AI disclosure, self-harm protocol, break reminders for known minors, reporting from Jul 2027); FTC 6(b) inquiry; Character.AI added age verification. | Law-firm summaries | Applies to operators. Matters only if Celestia is ever distributed. T14 stays small. |
| **Windows is becoming an agent platform** (MCP in Windows, Agent Workspace; Build 2026 reportedly added an agent runtime and execution containers). | Unverified | Watch, don't build on. If it lands, an OS container could sandbox `run_powershell`. Our edge is memory + companion + local, not being a runtime. |

## 2. Positioning, updated

Sep wording still holds. Add one clause: **free, offline Windows companion on an 8–12 GB NVIDIA
GPU that sees the screen, keeps an inspectable time-aware memory, and *asks before it acts* —
every action audited, gated, undoable.**

- OpenClaw-style agents win on reach and lose on trust. We win on trust.
- Cloud assistants win on integrations and lose on locality. A local daily brief competes there.
- Windows will absorb generic "do things on my PC". Our value is memory, presence and approvals.

## 4. Tasks

Existing IDs keep their meaning; changed scope is noted. Sizes: **S** ≤ 1 week · **M** 2–4
weeks · **L** 1–2+ months.

### Changed

- **T02 (extend):** GPU runs of the candidate set above on the owner's card. Set `num_ctx`
  explicitly (library defaults are 128–256K and the KV cache will not fit). Decision rule is
  unchanged (D2). If one model wins both, drop `vision.unload_chat_model`.
- **T05 (extend):** order of fallback is Orpheus (GPU) → **Kokoro (CPU, local)** → text-only. Edge
  TTS only with `voice.tts.allow_cloud_fallback: true` and labelled "cloud voice".
- **T08 (widen, P0, M):**
  1. `armed_ttl_minutes` and the countdown (as planned).
  2. **Per-command confirmation** for state-changing PowerShell in any mode.
  3. **Rule-of-Two gate:** once a turn has ingested untrusted text (`untrusted.turn_tainted`),
     every state-changing or outbound tool needs explicit approval, even in armed mode. Builds on
     what T04 already does for memory tools.
  4. **Approval channel:** pending-approval SSE event + token-guarded `POST /approvals/{id}`,
     with the decision audited. Generic, so MCP `input_required` (T19) can use it.
  - *Acceptance:* tests for expiry, taint gating, approve/deny/timeout; Console B3 can render it.
- **T09 (reorder):** depends on T10 as well as T04 and T07.

## 7. Risks and unknowns

- **Source quality.** Several figures are secondary or vendor claims; see **[VERIFY]**. None of
  the P0 work depends on them: the Rule of Two and OpenClaw's failure modes are enough on their own.
- **Ollama churn.** Releases are frequent (v0.40.x in Nov 2026). Keep the CI pin (T02) and re-run
  the evals on bumps. Ollama also pushes cloud models; keep them out of the picker (D5).
- **Hardware assumption.** All model fit statements assume an 8–12 GB NVIDIA card. `gemma4:12b`
  (7.7–8 GB) only makes sense at 12 GB once STT/TTS are resident.
- **T15 size.** The branch is large (~4.6k lines). Land it in reviewable pieces, with T16 as acceptance.
- **Small-model ceiling.** The approval and taint gates assume the model can follow a
  "needs approval" result. T03 must cover that.
